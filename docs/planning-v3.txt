SECTION 1: PROJECT OVERVIEW
================================================================================

1.1 PRODUCT NAME
    menaRun

1.2 ELEVATOR PITCH
    An event-based fitness leaderboard platform where participants register
    once (no login required), receive a unique token, and submit Strava activity
    links to compete in admin-managed events. Admins manage events and monitor
    participant data via a protected dashboard.

1.3 TARGET USERS

    PARTICIPANTS (no login):
    - Register with personal data (name, AIMS number, majlis, email, age, phone)
    - Receive a unique token after registration
    - Use token to submit Strava activity links per event
    - View public leaderboard filtered by event

    ADMINS (login required):
    - Manage events (create, edit, delete, activate/deactivate)
    - View and search participant data
    - Export participant data [NICE]

1.4 CORE VALUE PROPOSITION
    - Zero friction for participants: register once, save token, submit activities
    - No password, no login, no app install for participants
    - Real-time event leaderboard with Strava auto-parsing
    - Single deploy on Vercel — zero server ops

1.5 PLATFORM

    USER-FACING APP:
    - Web app (Next.js App Router)
    - MOBILE-FIRST responsive design (assume 80%+ users on phone browser)
    - Optimized for screen width 360px–430px
    - Must remain usable up to 1920px desktop
    - Aesthetic: minimalist retro pixel/8-bit vibes on light broken-white base
      with hijau tosca accents; includes logo and short Mario-style celebration
      animation after successful form submissions

    ADMIN PANEL:
    - Web app (desktop-first, table-heavy UI)
    - Built as /admin routes in same Next.js project
    - Accessed at: /admin (protected by Auth.js middleware)
    - Only accessible by users in the `admins` table

1.6 KEY DIFFERENCES FROM v2

    REMOVED:
    - User login/register with password (participants)
    - Communities, community members, invite links
    - User profiles, avatars, personal stats pages
    - Gamification (points, streaks, levels, achievements)
    - Filament admin panel
    - Laravel backend, Sanctum tokens
    - Separate React SPA (apps/web) and Laravel API (apps/api)

    ADDED:
    - Participant registration with token issuance
    - Unique AIMS number as identity credential
    - Event-based competition (not community-based)
    - Token-based activity submission (no login)
    - Daily submission rate limit (2 per token per day)
    - Custom admin dashboard in Next.js
    - "Lupa Token?" recovery flow via AIMS + email

4.7.3 ANIMATION SEQUENCE (total ~2.5 seconds)

    Step 1 (0.0s – 0.6s): Backdrop fades in (opacity 0 → 1, steps easing)
    Step 2 (0.2s – 1.0s): Runner sprite enters from left, bounce-walks to center
              - Use CSS @keyframes with steps(4) for choppy pixel movement
              - Sprite: public/images/celebration/runner-sprite.png [DUMMY]
              - Size: 48 × 48 px, image-rendering: pixelated
    Step 3 (0.8s – 1.4s): Flag icon pops up from behind runner (scale 0 → 1, steps)
              - Simple pixel flag: CSS div or small PNG sprite
              - Color: tosca + broken white stripes
    Step 4 (1.0s – 2.0s): Text "Mubarak! Khuddam Zindabad!" appears
              - Font: Press Start 2P, 10–12px mobile, color: tosca-dark
              - Animation: scale from 0 to 1 with steps(6), slight bounce
              - Line break allowed on mobile: "Mubarak!" / "Khuddam Zindabad!"
    Step 5 (1.4s – 2.2s): 5–8 pixel star particles burst outward (CSS only)
              - Small 4×4 px squares, tosca + gold (#E5A100), fade out
    Step 6 (2.2s – 2.5s): Whole overlay fades out → onComplete() called
              - Parent shows success content (token card or activity summary)

    Implementation: framer-motion with steps easing OR pure CSS @keyframes.
    Prefer CSS @keyframes for performance on mobile. No external sprite sheet
    library required.

4.7.4 INTEGRATION FLOW

      3. Client sets showCelebration=true (no redirect)
      4. PixelCelebration overlay plays (~2.5s)

5.3 MIDDLEWARE LOGIC (middleware.ts)

    - Match paths: /admin/*

    - If no session: redirect to /login?callbackUrl=/admin
    - If session exists: allow through

SECTION 7: BUSINESS RULES
================================================================================

7.1 PARTICIPANT REGISTRATION

    Required fields:
      - nama        : string, 2–100 chars, letters and spaces only
      - no_aims     : string, exactly 5 numeric digits (/^\d{5}$/)
      - majlis      : string, must match an entry in majlis table (dropdown)
      - email       : string, valid email format
      - usia        : integer, range 10–99
      - no_hp       : string, Indonesian phone format, normalized to 08xxxxxxxxxx

    On submit:
      1. Validate all fields (Zod schema)
      2. Check no_aims is NOT already registered (UNIQUE constraint)
         → If duplicate: return error (see 7.1.1)
      3. Generate unique 8-char uppercase alphanumeric token (nanoid custom alphabet)
         → Retry up to 5 times if collision (extremely unlikely)
      4. Insert participant record
      5. Redirect to /registrasi/sukses?token={token}

    7.1.1 DUPLICATE AIMS ERROR
      Message (Indonesian):
        "No. AIMS {no_aims} sudah terdaftar. Jika Anda sudah memiliki token,
         gunakan menu Input Aktivitas. Jika lupa token, gunakan menu Lupa Token."

    7.1.2 TOKEN DISPLAY PAGE (/registrasi/sukses)
      Flow:
        1. Page loads → PixelCelebration animation plays first (~2.5s)
           Text: "Mubarak! Khuddam Zindabad!"
        2. onComplete → reveal token card

      Token card content:
      - Show token in large, copyable text (monospace font, tosca color)
      - Warning message [MUST]:
        "Ingat dan simpan token ini. Token diperlukan setiap kali Anda
         menginput aktivitas. Token tidak dapat dipulihkan tanpa No. AIMS
         dan email yang terdaftar."
      - Buttons: [Input Aktivitas] → /input  |  [Kembali ke Beranda] → /
      - [NICE] Copy-to-clipboard button for token

7.2 TOKEN RECOVERY (/lupa-token)

    Form fields:
      - no_aims : 5-digit AIMS number
      - email   : registered email address

    On submit:
      1. Find participant WHERE no_aims = input AND email = input
      2. If found: display token with same warning as registration success page
      3. If not found: "No. AIMS dan email tidak cocok. Periksa kembali data Anda."
      4. Rate limit: max 5 attempts per IP per hour [SHOULD]

    Security note:
      - Requires BOTH AIMS + email to match (not AIMS alone)
      - Do NOT send token via email in MVP (display on screen only)
      - [POST-MVP] Send token via email/SMS

7.3 ACTIVITY SUBMISSION

    Form fields:
      - token      : string, required (participant's token)
      - strava_url : string, valid Strava share URL
      - event_id   : UUID, must be an active event (dropdown of active events)

    On submit (Server Action: submitActivity):
      1. Validate form fields (Zod)
      2. Find participant by token
         → If not found: "Token tidak valid. Periksa kembali token Anda."
      3. Check daily rate limit (see 7.4)
         → If exceeded: "Token ini sudah mencapai batas 2 aktivitas hari ini. Coba lagi besok."
      4. Validate event exists and is_active=true
         → If not: "Event tidak aktif atau tidak ditemukan."
      5. Parse Strava URL (see SECTION 8)
         → Extract activity_date from OG meta tags (og:description, article:published_time)
         → If parse fails: "Link Strava tidak dapat dibaca. Pastikan link valid dan publik."
      6. Check activity_date is within event date range (inclusive, WIB date-only)
         → If not: "Aktivitas tertanggal {activity_date} di luar periode event
           ({tanggal_mulai} – {tanggal_selesai})."
         → Example: event 16–26 Jun 2026, activity dated 14 Jun 2026 → REJECTED
      7. Check strava_activity_id is not already submitted (globally unique)
         → If duplicate: "Aktivitas Strava ini sudah pernah disubmit."
      8. Compute pace_per_km from distance_km and duration_sec
      9. Insert activity record
      10. Return success with summary:
          { nama, distance_km, duration, pace, sisa_kuota_hari_ini }

      Client-side after success:
        1. Play PixelCelebration overlay (~2.5s) — "Mubarak! Khuddam Zindabad!"
        2. onComplete → show activity summary card + remaining daily quota

    [NICE] Preview step:
      - Before final submit, call POST /api/strava/parse to show parsed preview
      - User confirms before saving

7.4 DAILY RATE LIMIT

    Rule: Each token may submit MAXIMUM 2 Strava activities per calendar day.

    Timezone: Asia/Jakarta (WIB, UTC+7)
    Reset: midnight WIB (00:00)

    Implementation:
      COUNT activities WHERE participant_id = X
        AND submitted_at >= start_of_today_WIB
        AND submitted_at < start_of_tomorrow_WIB

    Limit is GLOBAL per token (across all events), not per event.

    Response when limit reached:
      "Token ini sudah mencapai batas 2 aktivitas hari ini. Coba lagi besok."

    Display remaining quota after successful submit:
      "Aktivitas berhasil disimpan. Sisa kuota hari ini: {2 - count} aktivitas."

7.5 LEADERBOARD

    Default metric: TOTAL distance_km per participant within selected event.
    Tiebreaker: total activity count (more activities wins).
    Second tiebreaker: earlier first submission timestamp.

    Query (pseudocode):
      SELECT
        p.nama, p.majlis, p.no_aims,
        SUM(a.distance_km) AS total_distance,
        COUNT(a.id) AS activity_count,
        AVG(a.duration_sec / a.distance_km) AS avg_pace_sec
      FROM activities a
      JOIN participants p ON a.participant_id = p.id
      WHERE a.event_id = :eventId
      GROUP BY p.id
      ORDER BY total_distance DESC, activity_count DESC

    Display columns:
      Rank | Nama | Majlis | Total Jarak (km) | Jumlah Aktivitas | Pace Rata-rata

    Event filter:
      - Dropdown showing all events (active shown first, with label)
      - Default selection: "event terkini" (see 6.2 notes)
      - Changing filter reloads leaderboard data

    Podium: top 3 displayed with pixel-style podium component (TopThreePodium)

    [NICE] Period filter within event: minggu ini / bulan ini / semua

SECTION 8: STRAVA DATA EXTRACTION
================================================================================

8.1 OVERVIEW

    Strava share links are parsed server-side by fetching the public HTML page
    and extracting Open Graph meta tags. NO Strava OAuth or official API is used.

    Port logic from v2: apps/api/app/Services/StravaParserService.php
    To: lib/strava-parser.ts using cheerio

8.2 SUPPORTED URL FORMATS

    https://www.strava.com/activities/{id}
    https://www.strava.com/activities/{id}/share
    https://strava.app.link/{code}          ← redirect, follow to resolve

8.3 EXTRACTION PRIORITY

    Field            Source (priority order)
    -----            -----------------------
    strava_activity_id  Extract numeric ID from URL path
    title            og:title meta tag
    distance_km      og:description regex OR structured data
                     Pattern: "X.XX km" or "X,XX km" or "X.XX mi" (convert)
    duration_sec     og:description regex
                     Pattern: "MM:SS" or "H:MM:SS" for moving/elapsed time
                     Prefer moving time label; fallback elapsed time
    activity_date    og:description date OR article:published_time meta
    sport_type       og:description keyword: "Run", "Ride", "Swim", "Walk"
                     MVP: accept all types (no filter), store as-is
    raw_meta         Snapshot of all extracted OG tags (JSON blob for audit)

8.4 PACE CALCULATION

    pace_sec_per_km = duration_sec / distance_km
    Format as "M:SS" string:
      minutes = Math.floor(pace_sec_per_km / 60)
      seconds = Math.round(pace_sec_per_km % 60)
      pace_per_km = `${minutes}:${seconds.toString().padStart(2, '0')}`

    Only compute if distance_km > 0

8.5 PARSE API ENDPOINT

    POST /api/strava/parse
    Body: { strava_url: string, event_id?: string }
    Response: { data: { distance_km, duration_sec, duration_type, pace_per_km,
                        activity_date, title, sport_type } }
    Error:   { error: { code, message } }

    When event_id is provided: also validates activity_date within event period.
    Returns OUTSIDE_EVENT_PERIOD if activity date falls outside event range.

    Rate limit: 10 requests per minute per IP [SHOULD]
    Cache: parsed result cached 24h by strava_activity_id [NICE]

    Used for preview before submit [NICE]. Direct submit also parses inline.

8.6 ANTI-CHEATING VALIDATION

    [MUST] strava_url must contain "strava.com"
    [MUST] activity_date must not be in the future (WIB timezone)
    [MUST] strava_activity_id globally unique (one link = one submission ever)
    [MUST] strava_activity_id unique per event (double protection)
    [SHOULD] distance_km must be > 0
    [SHOULD] distance_km must be < 200 (sanity check for ultra distances)
    [NICE] Flag activities with distance_km > 50 for admin review

8.7 ERROR MESSAGES (Indonesian)

    Code                  Message
    ----                  -------
    INVALID_URL           "Link Strava tidak valid. Pastikan URL mengandung strava.com"
    PARSE_FAILED          "Tidak dapat membaca data aktivitas. Pastikan link publik dan valid."
    FUTURE_DATE           "Tanggal aktivitas tidak boleh di masa depan."
    DUPLICATE_ACTIVITY    "Aktivitas Strava ini sudah pernah disubmit."
    RATE_LIMIT_EXCEEDED   "Token ini sudah mencapai batas 2 aktivitas hari ini."
    INVALID_TOKEN         "Token tidak valid. Periksa kembali token Anda."
    EVENT_INACTIVE        "Event tidak aktif atau tidak ditemukan."
    OUTSIDE_EVENT_PERIOD  "Aktivitas tertanggal {date} di luar periode event ({mulai} – {selesai})."

SECTION 13: TOKEN GENERATION
================================================================================

13.1 ALGORITHM (lib/token-generator.ts)

    import { customAlphabet } from 'nanoid'

    // Uppercase letters + digits, no ambiguous chars (0/O, 1/I/L)
    const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ'
    const generate = customAlphabet(ALPHABET, 8)

    export async function generateUniqueToken(): Promise<string> {
      // Retry up to 5 times on collision (extremely unlikely with 32^8 combinations)
      for (let i = 0; i < 5; i++) {
        const token = generate()
        const exists = await prisma.participant.findUnique({ where: { token } })
        if (!exists) return token
      }
      throw new Error('Failed to generate unique token')
    }

    Token properties:
      - Length: 8 characters
      - Charset: 23456789ABCDEFGHJKMNPQRSTUVWXYZ (30 chars, no ambiguous)
      - Total combinations: 30^8 = ~656 billion
      - Case: always UPPERCASE
      - Example: "K7M2P9XA"

    Do NOT use sequential numbers (00001, 00002) — too guessable.

- ❌ Do NOT build gamification, communities, or user profiles — out of scope for v3
- ❌ Do NOT use Laravel, Filament, or Sanctum — this is a Next.js project
- ❌ Do NOT hard-code API URLs — no separate API exists, use Server Actions

SECTION 19: GLOSSARY
================================================================================

AIMS        : Ahmadiyya Muslim Jama'at identification number (5-digit numeric ID)
Token       : 8-character alphanumeric code issued to participant after registration
Majlis      : Local chapter/organization unit (~160 exist, used as dropdown in registration)
Event       : A time-bounded competition period managed by admin
Activity    : A single Strava activity submission (link + parsed metadata)
Pace        : Average speed per kilometer, formatted as "M:SS" (minutes:seconds)
Leaderboard : Ranking of participants by total distance within an event
Server Action: Next.js server-side function called directly from client components
WIB         : Waktu Indonesia Barat (UTC+7), used for daily rate limit reset
